# Predict Bike Sharing Demand with AutoGluon

Predict hourly bike rental demand (`count`) for the Kaggle
[Bike Sharing Demand](https://www.kaggle.com/c/bike-sharing-demand) competition using
AutoGluon's tabular AutoML. The notebook runs three rounds of training and compares
them:

1. **Baseline**: raw features as downloaded from Kaggle. Kaggle score (RMSLE) ~1.38.
2. **Feature engineering**: split `datetime` into year/month/day/hour and cast cyclical
   columns to categorical. Kaggle score ~0.55.
3. **Feature engineering + tuning**: normalized weather columns, hyperparameter search
   (20 trials per model type, local scheduler), heavier bagging and stacking.
   Kaggle score ~0.50.

The biggest gain came from feature engineering; tuning added a smaller but consistent
improvement.

## How to run

1. Install the dependencies:
   ```
   pip install -r requirements.txt
   ```
2. Create a Kaggle account and an API token (Account settings > API > Create New API Token).
   Export the credentials so the notebook can pick them up; never hard-code them:
   ```
   export KAGGLE_USERNAME="your-username"
   export KAGGLE_KEY="your-api-key"
   ```
   Then open `project-template.ipynb` and run the cells in order. The notebook writes the
   credentials to `~/.kaggle/kaggle.json` and downloads the competition data with the
   `kaggle` CLI. (The CSVs are already committed here, so you can also skip straight to
   the training cells.)
3. Each training round is limited to 10 minutes with the `best_quality` preset, so a full
   run takes roughly 30 minutes of training plus submission time. A GPU is not required.
4. Submit a prediction file with:
   ```
   kaggle competitions submit -c bike-sharing-demand -f submission.csv -m "message"
   ```

## What you learn

- Using `TabularPredictor` for regression with a custom metric (`root_mean_squared_error`)
  and time limits.
- Reading the AutoGluon leaderboard and `fit_summary()` to compare models.
- Why feature engineering matters for AutoML: extracting hour/day/month from a timestamp
  and declaring categorical dtypes cut the error by more than half.
- Running hyperparameter search via `hyperparameter_tune_kwargs` with bagging and
  multi-level stacking.
- Practical submission hygiene: clamping negative predictions to zero before submitting.
